# M5.5 — Adversarial Backfill (Pre-M6 Hardening)

> Process initiative, not a feature milestone. Retrofit adversarial / failure-mode test
> coverage onto M1–M5 under the new `docs/best-practices/dev-qa-cycle.md` rules before
> M6 starts. No new product surface; no new ADRs unless an adversarial finding forces a
> contract revision.

## Why

The M5 review cycle took 5 rounds. The reviewers did eventually surface every defect
(phantom OPEN, arm-before-await ordering, drift clamping, awaitPolicyTimeout branches,
HaltFlagService injection gap), but the QA waves at W3 and W5d ran happy-path tests
only. Real state-machine bugs bubbled through three review rounds because no test
tried to break the implementation between waves.

`dev-qa-cycle.md` §2 now codifies adversarial QA as the bar for done. Before M6 we want
two things:

1. **Foundation hardening.** M6 (position management) depends on the M2 schema, the M3
   strategy contract, the M4 risk gate, and the M5 execution state machine being
   correct under failure modes — not just under the happy path. M6 will write the
   protective-monitor evaluation loop, reconciliation on boot, and re-arm of OPEN
   positions whose status was never persisted. Each of those depends on lower-layer
   invariants the happy-path suites do not exercise.
2. **Dogfooding the new process on known terrain.** M5 is the most recent milestone and
   its review history is the answer key. Re-running the new adversarial-QA + architect-
   triage + reviewer-resume pattern against M5 validates the rule before it has to
   carry M6.

## Sequencing

Bottom-up, with M5 inserted ahead of M1 deliberately:

**M2 → M3 → M4 → M5 → M1**

Reasoning:

- Each adversarial pass runs against an already-hardened layer below, so any failure
  stays localized to the milestone under test rather than cascading.
- M5 sits before M1 because it is the most recently reviewed surface and the calibration
  case for the new process. Validating dev-qa-cycle on M5 confirms the rules before
  M1 gets its turn.
- M1 is last. It is the ingestion edge — failures there (mis-bucketed bars, calibration
  drift, missing OI samples) are easier to reason about once persistence, strategy,
  risk, and execution are known to handle malformed inputs correctly.

## Per-milestone plans

### M2 — Persistence

**Surfaces (5):**

1. **NUMERIC ↔ Decimal transformer at column boundaries.** Values exceeding declared
   NUMERIC precision/scale, negative zero, exponent-form strings, `NaN`/`Infinity`
   from upstream computation, and the explicit-JS-number rejection path.
   - Files: `apps/engine/src/persistence/transformer/DecimalColumnTransformer.ts`,
     `apps/engine/src/persistence/transformer/MoneyColumnTransformer.ts`.
2. **`tick_aggregates` partition boundary at the second/microsecond seam.** Insert at
   the exact partition cutover instant, insert into a partition that does not yet
   exist (partition-create race), and insert backdated rows older than the 90-day
   retention edge.
   - Files: `apps/engine/src/persistence/migrations/*tick_aggregates*.ts`,
     `apps/engine/src/market-data/persistence/TickAggregateRepository.ts`.
3. **Migration up → down → up round-trip under simulated row volume.** Run the
   reversible chain against a database that already holds rows in every entity;
   confirm `down()` drops indexes in reverse order and `up()` re-creates without
   collision. Caught in M2 round 1 only after smoke testing.
   - Files: all `apps/engine/src/persistence/migrations/*.ts`.
4. **Unique-constraint races on concurrent inserts.** Two writers racing for the
   `universe_membership` partial unique index `UNIQUE(symbol) WHERE left_at IS NULL`;
   two listeners racing on `candles UNIQUE(symbol, interval, open_time)`; two
   `funding_rates` writers using the same settlement timestamp.
   - Files: `apps/engine/src/market-data/persistence/UniverseMembershipRepository.ts`,
     `apps/engine/src/market-data/persistence/CandleRepository.ts`,
     `apps/engine/src/market-data/persistence/FundingRateRepository.ts`.
5. **Zod-validated `market_snapshot` write under schema drift.** Missing required
   field, unknown extra field after `.strict()`, and `decimal` field arriving as a
   JS number. Today this warns rather than throws — confirm the warn path is taken
   and the row is still rejected at the column boundary.
   - Files: `packages/shared/src/schema/marketSnapshotSchema.ts`,
     `apps/engine/src/strategy/persistence/DecisionRepository.ts`.

**ADR clauses falsified:**

- ADR 0002 §money-as-decimal: surface 1 falsifies "no float reaches a NUMERIC column."
- ADR 0002 §tick-aggregate retention + partitioning: surface 2 falsifies "every
  insert lands in the partition for its `ts`."
- ADR 0002 §reversible migrations: surface 3 falsifies "every up() has a clean
  down()."
- ADR 0002 §point-in-time universe (one open row per symbol): surface 4 falsifies
  "no two open `universe_membership` rows for the same symbol can ever coexist."
- ADR 0002 §market_snapshot Zod contract: surface 5 falsifies "a decision write that
  violates the snapshot contract never lands as silently corrupt JSONB."

**Expected outcome:** 0–2 findings. Round 1 was thorough on these surfaces; the most
likely residual is a partition-boundary or retention edge that was never explicitly
unit-tested.

**Out of scope:**

- Happy-path entity CRUD (M2's existing tests cover this).
- Repository query shape audits (clean-code concern).
- Schema design re-litigation (locked in ADR 0002).
- OI / funding / book_snapshots happy-path persistence (covered by M2 smoke).

### M3 — Strategies

**Surfaces (5):**

1. **Strategy determinism under repeated evaluation of the same `IStrategyInput`.**
   Run each of v0–v3 N times against the same frozen input; confirm bit-identical
   `ISignal` output, no observable hidden state, no clock read.
   - Files: `apps/engine/src/strategy/v0/`, `v1/`, `v2/`, `v3/`,
     `apps/engine/src/strategy/service/StrategyService.ts`.
2. **`nowMs` derivation always from the bar, never wall-clock.** Inject a strategy
   input whose `entry_candle_open_time` is far in the past; confirm `time_stop_at`
   is computed off the bar, not `Date.now()`. Backtest-vs-live parity invariant.
   - Files: `apps/engine/src/strategy/service/StrategyService.ts`,
     all four version directories' stop computation helpers.
3. **`flow_type` + `signal_score` stamped exactly once on `market_snapshot`.**
   Replay the same `volatility.detected` event; confirm classification runs once
   and downstream versions see the orchestrator-stamped value, not re-derived.
   Adversarial case: event arrives with a pre-populated stale `flow_type` — does
   the orchestrator overwrite or leak?
   - Files: `apps/engine/src/strategy/service/StrategyService.ts`,
     `packages/shared/src/util/classifyFlowType.ts`,
     `packages/shared/src/util/computeSignalScore.ts`.
4. **v1 exhaustion confirmation tightness.** Inject a still-extended spike where
   `%B` has not crossed back, plus the boundary cases at `%B = 0.8` / `%B = 0.2`
   exact; confirm v1 emits `skip` with `no_exhaustion_confirmation`. Caught in
   M3 round 1 medium — re-test for regressions.
   - Files: `apps/engine/src/strategy/v1/`.
5. **v3 router fallthrough on unknown / missing `flow_type`.** Inject an event with
   `flow_type = undefined`, a future enum value, and the `low_quality_noise` case;
   confirm router routes to `skip`, never raises, never invents a direction.
   - Files: `apps/engine/src/strategy/v3/`.

**ADR clauses falsified:**

- ADR 0003 §pure-and-deterministic: surfaces 1, 2 falsify "no `Date.now()` /
  `Math.random()` / I/O inside a strategy."
- ADR 0003 §single-stamp-orchestrator: surface 3 falsifies "every version of a given
  trigger event reads the same `flow_type` / `signal_score`."
- ADR 0003 §skip-is-first-class + exhaustion-confirmation: surface 4 falsifies
  "v1 must not enter on the first close outside the band."
- ADR 0003 §v3-routing-is-deterministic: surface 5 falsifies "an unknown classifier
  output never produces a direction signal."

**Expected outcome:** 0–1 findings. Round 1 caught the dead-code trap guard and the
loose v1 confirmation; round 2 closed clean-code residuals. The remaining risk is
the v3 fallthrough on schema drift, which was never explicitly adversarial-tested.

**Out of scope:**

- `classifyFlowType` taxonomy re-derivation (locked in ADR 0003).
- Strategy parameter values (config concern).
- Stop math correctness on known candles (covered by M3 unit tests).

### M4 — Risk gate

**Surfaces (5):**

1. **Two simultaneous intents racing for the same slot.** Two `volatility.detected`
   events approved in the same event-loop tick when only one slot remains; confirm
   exactly one reservation lands and the second is rejected `max_positions_reached`.
   Mirror with slot C for two BTC-correlated candidates in the same bar window.
   - Files: `apps/engine/src/risk/service/RiskService.ts`,
     `apps/engine/src/risk/persistence/InFlightReservationRepository.ts`.
2. **Reservation leak when an event handler throws mid-flight.** Approve an intent
   (reservation written), then have the downstream handler throw before the order
   intent is emitted; confirm the reservation TTL releases and a subsequent intent
   on the same slot is approved. Crash window between insert and downstream emit.
   - Files: `apps/engine/src/risk/service/RiskService.ts`, reservation TTL helper.
3. **Loss window straddling UTC midnight and the rolling-7-day cutoff.** Realized
   loss recorded at 23:59:59.999 UTC vs 00:00:00.000 UTC; confirm the daily window
   resets at the boundary and the rolling-7-day SUM excludes the day rolling off.
   - Files: `apps/engine/src/risk/persistence/RiskStateRepository.ts`,
     `apps/engine/src/risk/service/RiskService.ts`.
4. **Halt fired between reservation and order intent emission.** Reservation
   approved; `HaltFlagService` flips to true before the order intent is published;
   confirm the intent is dropped and the reservation is released. Also test the
   reverse: kill-switch flatten arrives while gate is mid-evaluate.
   - Files: `apps/engine/src/risk/service/RiskService.ts`,
     `apps/engine/src/common/service/HaltFlagService.ts`.
5. **Cooldown / per-bar / consecutive-loss evasion via rapid resubmit.** Same
   symbol re-emits `volatility.detected` immediately after a closed loss; same-bar
   second trigger from any symbol; (N+1)th consecutive-loss-day entry. Includes the
   round-2 per-bar off-by-one (`createdAtMs === nowMs` boundary).
   - Files: `apps/engine/src/risk/service/RiskService.ts`,
     `apps/engine/src/risk/persistence/InFlightReservationRepository.ts`.

**ADR clauses falsified:**

- ADR 0004 §bypass-proof gate (all actions through one evaluate): surfaces 1, 2, 4
  falsify "no order action reaches execution without passing the gate, and no
  approval leaks if downstream throws."
- ADR 0004 §loss-window definitions: surface 3 falsifies "the daily boundary is
  exactly UTC midnight and the weekly window is exactly the rolling 7 days."
- ADR 0004 §halt-overrides-everything: surface 4 falsifies "no approved intent
  survives a halt set after approval."
- ADR 0004 §overtrading-caps + cooldown: surface 5 falsifies "(N+1)th entry never
  passes the gate within the cap window."

**Expected outcome:** 1–3 findings. Risk gate is the densest state-machine surface
and the one M6 leans on hardest. The per-bar off-by-one in round 2 suggests other
boundary cases (loss window seams, reservation TTL race) are likely under-tested.

**Out of scope:**

- ADD-not-vetted-by-gate carry-over (locked deferred per M4 outcome).
- Position sizing math on known instruments (M4 unit-tested).
- Tier-3 / OI-required policy (already explicit rejections).
- Funding-as-skip taxonomy re-derivation.

### M5 — Execution

**Surfaces (5):**

1. **Idempotency replay on UNKNOWN reject.** Submit an order, fail with the timeout
   path that produced M5 round-1 blocker; restart engine; confirm clientOrderId
   query lands one row, not zero or two. Also test the deterministic
   `clientOrderId` collision case (same intent re-emitted by retry path).
   - Files: `apps/engine/src/execution/service/ExecutionService.ts`,
     `apps/engine/src/execution/util/clientOrderId.ts` (or equivalent),
     `apps/engine/src/execution/util/classifyAuditFailure.ts`.
2. **arm-before-await invariant on LocalProtectiveMonitor.** Crash window between
   the order place response and the monitor arm; crash window between disarm and
   close acknowledgment. M5 round 1 caught this once — re-test for regression.
   **Scope clarification:** this surface validates only the **contract** M6's
   boot-resync will rely on — i.e. that after a crash, `protective_order_type =
   local_fallback`, `position.status` is correct, and the row is visible to a
   future M6 boot scan. The boot-resync **logic itself stays M6 scope** and gets
   its own adversarial coverage when M6 implements it. Do NOT pull the resync
   forward into this pass.
   - Files: `apps/engine/src/execution/service/LocalProtectiveMonitor.ts`,
     `apps/engine/src/execution/service/ExecutionService.ts`.
3. **Partial-fill recompute on weighted-average ADD.** ADD to an open position with
   partial fill; confirm position notional, entry price, SL/TP are recomputed off
   the **actual** filled qty, not the intended qty. Boundary: zero fill, single-
   tick fill, full fill, fill larger than intent (exchange rounds up).
   - Files: `apps/engine/src/execution/service/FillAccumulator.ts`,
     `apps/engine/src/execution/service/ExecutionService.ts`.
4. **HaltFlagService gating on every retry hop.** Halt flips mid-retry on a
   RETRIABLE reject; confirm no further retry attempts. Same for the
   reconciliation-on-boot path.
   - Files: `apps/engine/src/execution/service/ExecutionService.ts`,
     `apps/engine/src/common/service/HaltFlagService.ts`.
5. **awaitPolicyTimeout per-policy boundary.** Each policy in the execution matrix
   exercised at exactly its configured timeout, at timeout − 1ms, at timeout + 1ms;
   confirm cancel-vs-leave-resting decision matches policy. M5 round 2 caught the
   global-vs-per-policy bug — re-test for regression.
   - Files: `apps/engine/src/execution/constants/executionConsts.ts`,
     `apps/engine/src/execution/service/ExecutionService.ts`.

**ADR clauses falsified:**

- ADR 0006 §idempotency contract: surface 1 falsifies "any of open/add/reduce/close
  replayed places at most one order."
- ADR 0008 §always-protected invariant: surface 2 falsifies "no position is ever
  observed without exchange SL/TP or an armed local monitor."
- ADR 0007 §partial-fill semantics: surface 3 falsifies "exposure and protective
  levels always match the filled qty, not the intended qty."
- ADR 0006 §halt-gates-all-retries: surface 4 falsifies "no retry hop survives a
  halt flip."
- ADR 0005 §per-policy timeouts + no-chase: surface 5 falsifies "cancel-vs-resting
  decision matches the policy matrix at every timeout boundary."

**Expected outcome:** 0–3 findings. M5 went 5 rounds — the reviewers caught
everything they could see, but they were reviewing diffs, not adversarial test
output. Most likely residual: a boundary case in idempotency replay or a recompute
edge in partial-fill that the existing 898 tests do not exercise at the seam.

**Out of scope:**

- Deferred items already owned by M6 (LocalProtectiveMonitor evaluation loop,
  reconciliation on boot, REDUCE remainder escalation).
- Fee normalization deferred to M7/M8.
- Order policy matrix re-derivation (locked in ADR 0005).
- ccxt sandbox auth carry-over (memory item, separate).

### M1 — Market data

**Surfaces (5):**

1. **5-min bar close authority under late ticks and quiet symbols.** A tick arrives
   after the bar should have closed; a symbol receives no ticks for an entire bar
   window; the watermark sweep races the tick path. M1 round 2 found the half-
   applied bar-close fix — confirm exactly-once close holds at every seam.
   - Files: `apps/engine/src/market-data/service/CandleAggregator.ts` (or
     equivalent), `apps/engine/src/market-data/service/MarketDataService.ts`,
     the closed-bar watermark helper.
2. **Trigger formula determinism on identical inputs.** `evaluateTrigger` invoked
   N times on the same closed bar — bit-identical output; same inputs across
   live and a canned backtest fixture — bit-identical output. The single source of
   truth invariant.
   - Files: `packages/shared/src/util/evaluateTrigger.ts` (or wherever shared
     trigger lives), `apps/engine/src/market-data/service/MarketDataService.ts`.
3. **Session-anchored VWAP reset at UTC 00:00 and event-anchor switch.** Bar that
   closes at 23:59:59 UTC vs 00:00:00 UTC; explicit verification VWAP context does
   not silently carry across the reset. M1 round 1 high — regression-test.
   - Files: VWAP computation in
     `apps/engine/src/market-data/service/` (per-symbol indicator state).
4. **WebSocket reconnect mid-bar and universe-refresh during a forming bar.** Drop
   the WS during an active 5-min bar; confirm the bar finalizes deterministically
   (or is correctly discarded), no phantom close emitted. Universe refresh that
   evicts a symbol mid-bar — no stale bar emitted for the evicted symbol.
   - Files: `apps/engine/src/market-data/service/WebSocketClient.ts` (or
     equivalent), `apps/engine/src/market-data/service/UniverseManager.ts`.
5. **Empirical band calibration percentile floor.** Calibration with N < window
   samples; calibration crossing the nearest-rank floor convention; calibration
   for a newly-entered symbol with no history. M1 carry-over (d) — pin the
   convention before M7 has to mirror it.
   - Files: `apps/engine/src/market-data/service/BandCalibration.ts` (or
     equivalent).

- ADR 0001 §empirical-band-calibration: surface 5 falsifies "the calibration

## Per-milestone budget

Hard caps per milestone:

- **1 adversarial QA dispatch** to `bot-qa-engineer`, scoped to the ≤5 surfaces from
  the milestone's list. Prompt explicitly cites `dev-qa-cycle.md` §2.2 wording.
- **1 architect-triage dispatch** *if and only if* any adversarial test fails.
  Architect (this agent, resumed) classifies each failure as
  implementation-bug / contract-gap / test-harness-fidelity per dev-qa-cycle §2.2.
- **1 narrow engineer fix wave per architect classification**, ≤5 items / ≤5 files,
  per `dev-qa-cycle.md` §1. If the classification produces > 5 items, split into
  sequential waves with a mini-review between.
- **1 logic re-review** via `SendMessage` to the prior round's `bot-review-logic`
  `agentId` (per §3.1). Other reviewers stay dormant unless the architect routes a
  specific finding to them.
- **Hard cap: 3 rounds per milestone — STRICT for this initiative.** If a milestone
  has not converged (zero blockers + zero highs) at the end of round 3: **stop**.
  Document the unfixed finding(s) as a deferred item in that milestone's outcome
  section (with the owning future milestone named) and move to the next milestone.
  **No 4th round** — not even for a "clear, narrow-fixable bug." Rationale: these
  are old milestones being hardened on borrowed time; if a defect needs >3 rounds
  the scope was wrong, and the right move is to surface it via the deferred-item
  path rather than power through. **This strict posture is scoped to the backfill
  initiative only.** New milestone work (M6+) may adopt the pragmatic posture from
  `dev-qa-cycle.md` §6.3 (cycle until clean), since those rounds are paying for
  feature work, not retrofitting.

The orchestrator owns diff verification per `dev-qa-cycle.md` §5 after every wave.

## Tracking & lineage

- Punch-list numbering follows `dev-qa-cycle.md` §4.3: `round X.Y, item Z` per
  milestone. Lineage preserved across rounds in the orchestrator consolidation.
- **QA agent — fresh per milestone, NOT resumed.** Each milestone's adversarial
  pass spawns a new `bot-qa-engineer` agent. Rationale: less context pollution
  between unrelated layers (M2 persistence semantics vs M5 execution state
  machine), and a cold code-read on each milestone catches things a stale context
  would skim past. This is a deliberate deviation from `dev-qa-cycle.md` §3.2
  scoped to the backfill initiative — feature milestones (M6+) continue resuming
  the QA agent across rounds *within* a single milestone.
- **Reviewer continuity — resume the prior milestone's `agentId`.** The
  `bot-review-logic` `agentId` from the original M2 / M3 / M4 / M5 / M1 review
  cycle is the one resumed for that milestone's adversarial round (per §3.1).
  The orchestrator keeps the mapping. Other reviewers stay dormant unless the
  architect routes a specific finding to them.
- **Architect agent — resumed across milestones** (same `agentId` throughout the
  M2→M3→M4→M5→M1 sequence) to preserve ADR rationale and triage history (per §3.3).
