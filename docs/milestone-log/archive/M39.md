# M39 — Shadow-ledger close path + realized-PnL fidelity (W1+W2)

**Closed:** 2026-06-17

**Summary:** Repaired shadow-measurement completeness by freeing the virtual-ledger slot on each event (W1: in-pass close) and walking next-bar exits to produce non-degenerate counterfactual realized PnL (W2: deferred next-bar exit walk + D3 force_close guard). Unblocks D3 promotion gate.

## Deliverables

### W1 — In-pass close + rebuild (SHIPPED)

**Problem:** Shadow virtual positions were never closed despite `simulateShadowFill` resolving an exit. Under `max_open_positions: 1`, the first open occupied the single slot forever, starving opens count to ≈1 per version. On 2026-06-16, 247/251 gate evaluations rejected `max_open_positions_reached`.

**Solution:**
- Replaced dormant `intra_bar_stop` with `time_stop` in `ISimulatedFill.closeReason`, `IVirtualCloseInput.closeReason`, `IVirtualClosedTradeLogEntry.closeReason`, `simulatedFillSchema` (shared contract, JSONB).
- Extended `ShadowCloseBySymbolReason` to `'sl' | 'tp' | 'force_close' | 'time_stop' | 'reverse_signal'`.
- `VirtualPositionLedgerService.countConsecutiveLossesInRiskDay` now skips `force_close` entries (neither arms nor resets halt, preserves streak gate for genuine SL/time_stop losses).
- `ShadowStrategyOrchestratorService.runOneShadow`: After successful `tryOpen`, immediately call `closeBySymbol` with deterministic `${eventId}:exit` derived event ID and `nowMs` from `fill.closedAt` (or last-tick timestamp on null fallback).
- `rebuildLedger` replays resolved-exit rows as net-zero open-then-close (slot ends empty on restart); hollow/missed rows skip replay as before.
- Added `resolveCloseNowMs` helper; asymmetric-fill guard warns on mismatched exit-price/close-reason nullability.

**Tests (W1):** 13 new tests across 2 files.
- `VirtualPositionLedgerService.m39.spec.ts` — FC5, FC6: force_close semantics (skip streak).
- `ShadowStrategyOrchestratorService.m39.spec.ts` — IP1–IP3: in-pass close succeeds, slot frees, no duplicate_event_id; RB1–RB3: rebuild with resolved-exit row, rebuild with missed row, restart doesn't re-lock.
- Adversarial B10 tests updated for force_close-skip semantics; all suites pass.

**Review (W1):** 1 wave (4 parallel: security, logic, quant, clean-code). Zero blockers/highs after resolution.

**Outcome:** Slot freed on every event; opens count now accrues. Force_close exits (~entry) are no longer degenerate from the halt-gate perspective. W1 fixes the count but not the PnL value (still ~−fees on same-bar force_close). W2 makes realized series meaningful.

### W2 — Deferred next-bar exit walk + D3 force_close guard (SHIPPED)

**Problem:** With only same-bar `force_close` exits, the shadow realized-PnL series is near-zero-variance and guaranteed-slightly-negative (exit ≈ entry minus fee). Not admissible to the D3 promotion gate.

**Solution:** Replace same-bar `force_close` with true SL/TP/time_stop walk across next bar's `tick_aggregates` (borrowing `HistoricalFillAdapter.simulateIntrabarStop` model from backtest). Implement as deferred walk: after W1 frees the slot, check on next `runShadows` call whether next-bar's `entryCandleOpenTime >= nextBarOpenMs`, load ticks, and walk with `simulateIntrabarStop` → `sl`, `tp`, or `time_stop`. Upgrade `shadow_decisions.simulated_fill` JSONB in-place.

**Core engine changes** (`apps/engine/src/strategy/`):
- `ShadowStrategyOrchestratorService`: Added `IPendingDeferredWalk` and `INextBarWalkContext` DTOs (queued pending walks, per-symbol). On next `runShadows` call where event's entry time ≥ next-bar open time, load `tick_aggregates` and walk with `HistoricalFillAdapter.simulateIntrabarStop`. Result updates `shadow_decisions.simulated_fill` via repository method.
- `ShadowDecisionRepository`: Added `updateSimulatedFill(IUpdateSimulatedFillInput)` method using TypeORM `.update()`.

## M40 Re-qualification Note (2026-06-19)

**Re-qualification claim held in test; regressed in production June 10 → M40 deploy.**

M39's W2 deferred-walk upgrade (and M37's "non-degenerate realized PnL" claim) were contradicted by production data starting 2026-06-10: despite gate-allowed opens populating `shadow_decisions` at volumes of 73–110/day (June 10+), `simulated_fill` stayed at ~0/day through M40 deploy. Root cause (confirmed M40 D2.0): not a deferred-walk durability issue (mechanism (c) was ruled out — no W1-only rows exist, only truly absent fills), but an entry-reference mismatch in `isStopSideValid`. The stop-side guard validated the strategy's structural stop against the tick-derived signal-bar close (~1% off the strategy's `reconstructReferencePrice` reference), not the anchor the stop was drawn from. This divergence flipped the stop to the wrong side of the shadow entry, producing a reject with no fill. Live, operating on the actual taker fill price (within slippage of the strategy's reference), never rejected these.

**M40 D2 fix:** `isStopSideValid` now validates against `reconstructReferencePrice`, fills stay tick-derived, and when tick entry is already past the unchanged SL, the intrabar walk records an immediate structural stop-out (bounded ≈ −1R loss, not 0-qty miss). This restores parity: live holds → shadow holds.

**Re-qualification gate (B5):** After M40 D2 deploy, `shadow_decisions` over ≥1 full soak day must show (a) non-zero `simulated_fill` for gate-allowed opens AND (b) non-degenerate `close_reason` distribution (not ~100% `force_close` / not ~100% `missed`). Window must be post-deploy (June 10→M40 gap is hollow with zero fills; new window post-M40 is authoritative). M39's measurement infra (slot-freeing, deferred-walk upgrade on next-bar ticks, force_close-fraction gate) remains correct; the "non-degenerate" realized-PnL claim is revalidated post-M40.
