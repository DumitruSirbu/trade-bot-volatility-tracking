# M28 — Same-bar threshold recalibration + auto-resume wiring (DONE):

Code-only, no migration, engine restart only. Goal: stop `market_stress:same_bar` from burning whole trading days on routine correlated sessions. Root cause: `STRESS_SAME_BAR_HALT_COUNT=5` (using the strategy param `stress_same_bar_trigger_count`) was too hair-trigger for paper soak volume — every ~5 minor correlated ticks fired a full-day halt. Fix: decoupled gate threshold to new engine const `STRESS_SAME_BAR_HALT_COUNT=20`, leaving strategy param at 5 for `classifyFlowType` MARKET_BETA routing (intentionally separate decisions — parameter drives flow classification, not halt threshold). Wired same_bar into the M23 auto-resume mechanism: new const `STRESS_SAME_BAR_RESUME_COUNT=12` and `SAME_BAR_RESUME_CLEAR_TICKS=2` (breadth needs 3 for hysteresis stability). New `IResumeProfile` object bundles predicate + tick count + leg; `autoResumeMarketStress` takes profile object (cleaner than ≤2-arg cap). Replaced single `MARKET_STRESS_RESUME_ELIGIBLE_LEG` string with typed `MARKET_STRESS_RESUME_ELIGIBLE_LEGS` Set; both `RiskGateService` and `RiskListeners` now `.has()` instead of `===` (better for multi-leg future). **D6 — Pre-existing bug fixed: per-transition resume dedup.** Dedup was keyed on `{utcDate, leg, reHaltCount}` (was day-only), so a second same-day resume of a different leg would fail to emit its own RESUMED event. Now each leg transition fires independently. **D7 — Pre-existing bug fixed: RiskListeners leg-check generalized.** `onMarketStressResumed` only cleared the in-memory halt flag for breadth (leg=`:breadth`); same_bar and other legs would clear the DB row but leave the flag stale. Now all resume-eligible legs clear the flag.
