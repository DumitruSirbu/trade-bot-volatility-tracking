# M23 — Market-stress adaptive auto-resume

**Problem:** Every UTC-day breadth-triggered `market_stress` halt locked trading for the full day, even when the triggering signal mean-reverted within minutes. Concrete example (2026-06-05 02:45 UTC): market breadth collapsed to 8%, halt fired, market recovered by 07:00 UTC, but bot stayed locked until 00:00 UTC next day. This was **too punitive** for a transient 5-minute breadth spike. Loss-based halts (deserving full-day cooling) and non-breadth legs (slower, unvalidated) stayed locked; only breadth got adaptive resume. Paper-only initially (code-enforced via `MARKET_STRESS_AUTO_RESUME_ENABLED` flag); live activation gated on backtest + 14-day soak.

**Architecture:** New in-process resume predicate (`isGlobalStressed`, breadth-only) and hysteresis band (engage ≥40 distance, resume ≤30 distance); consecutive clean-tick counter (N=3 default, tunable, starting point not calibration) gates auto-resume. Per-day re-halt cap (3rd breadth re-halt → full-day lock reasserts, chatter protection). `halt_reason` extended from bare `market_stress` to `market_stress:<leg>` suffix (`:breadth` resume-eligible, others full-day locked); no migration (same varchar column, richer string). HaltFlagService + RiskGateService resume branch (before day-lock early return, gated on flag). Restart resets clean-tick counter to 0 (conservative); re-halt counter in-memory only (deferred persist to M11 `updated_at` work). Deterministic (in-process tick counting, no wall-clock control flow); proves safe via paired tests + backtest replay parity.

**Independent Composer review:** Quant pre-review uncovered 2 BLOCKERs (per-leg resume predicate must be global-breadth-only, not full disjunction; N=3 is a tunable starting point, not a calibration). Post-architect review (`docs/archive/independent-analysis/composer/M23-market-stress-adaptive-resume-review.md`): 4 MUST-FIX findings (canonical `halt_reason`/`HaltFlagService` contract with double-prefix bug, leg-classifier completeness + multi-leg precedence, restart semantics quirk + mitigation, paper-only code enforcement via boot flag) all APPLIED; 6 SHOULD-FIX findings (dedup emit re-halt, dashboard halt_reason query audit, event payload fields + cap-proximity flag, backtest replay parity test, stale-halt suffixed-reason coverage, merged breadth-calibration tech-debt row) all APPLIED; 10 decision-critique amendments all APPLIED or satisfied-by-existing.

**Tests:** 116 new in 4 suites (StressHaltEvaluator: leg-classifier per-engage-path + multi-leg `:multi` rule; RiskGateService: breadth halt auto-resume + clean-tick counter + hysteresis edges + per-day re-halt cap + loss-halt lock + NaN fail-closed + restart reset; HaltFlagService: haltedLeg field; HaltStateRestoreService: double-prefix fix round-trip + no re-prefix). Paired tests per fix item: same-tick resume→re-halt emits fresh halt event, backtest replay reproduces live resume tick identically, legacy bare `market_stress` rows default to full-day lock.

**Review cycle:** R1 (security CLEAN, logic CLEAN, clean-code CLEAN, quant pre-BLOCKER/pre-HIGH concerns all addressed in plan) → 2-wave fix cycle (implementation + Composer-review-findings fix wave) → R2 (4 reviewers, zero blockers, zero highs). ADR 0004 §6d added (breadth-only auto-resume mechanism, hysteresis engage/resume 40/30, per-day re-halt cap 3, in-memory restart quirk documented, `market_stress:<leg>` suffix encoding + single canonical string + no-double-prefix contract, leg-classifier enumeration `:same_bar`/`:invalid`/`:multi`, boot flag `MARKET_STRESS_AUTO_RESUME_ENABLED` paper-on/live-off enforcement, paper-first live-activation gate, in-process determinism).
