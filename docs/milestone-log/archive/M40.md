# M40 — Halt-exempt closes + shadow fill regression + stuck-position sweeper

**Closed:** 2026-06-19

**Summary:** Repaired three critical defects: (D1) halt blocks new risk only; protective closes always execute end-to-end (go-live blocker). (D2) shadow `simulated_fill` collapsed June 10→M40 due to stop-side validation against wrong entry reference; fixed by re-anchoring to strategy's own reference + tick-derived fill + intrabar walk. ## Deliverables

### D1 — Halt blocks new risk only; risk-reducing closes always execute (SHIPPED)

**Problem:** A global halt (operator kill-switch or programmatic market-stress) short-circuited **every** approved intent, including protective closes. Position #101 INJ long's time-stop (due 18:15) and stop-loss breach were both blocked for 2h12m until manual `/v1/control/resume` at 20:17. Two upstream layers (ADR 0004 §2, ADR 0021 §2.4/§2.5) already encoded "de-risking always allowed under halt," but the executor never enforced the scoping.

**Solution:**
- `ExecutionService` three halt gates (`:163` entry, `:565` per-attempt, `:808` reduce-remainder) all scoped by the **same** `isOpenOrAddIntent` predicate: OPEN/ADD still abort; REDUCE/CLOSE/FLATTEN submit, fill, and reach CLOSED end-to-end.
- A permitted close that **cleanly** fills transitions `CLOSING → CLOSED`, releasing the shared close slot via **both** producers: `PositionTimeStopEnforcer.onPositionStateTransitioned` (`:107`, time-stop path) and `LocalProtectiveMonitor.onPositionStateTransitioned` (`:227-232`, SL/TP-breach path — the actual #101 case).
- Non-clean-under-halt path is a **known residual** (not solved by D1): a permitted close that does not cleanly fill (retry exhausted, TERMINAL/ABORTED reject) routes to `handleReduceTerminal` non-clean, emits `ORDER_INTENT_UNKNOWN_EVENT`, row parks in `RECONCILING` with close slot still held. Under PAPER, `ReconciliationService.runTickNow` is a no-op, so the slot stays held. **Owned by D4's stuck-row sweep** (extended to cover `RECONCILING`-parked rows older than threshold, reclaiming the close slot and finalizing).

### D2 — Shadow `simulated_fill` regression (SHIPPED; implementation reversed after architect verdict)

**Problem:** Gate-allowed OPEN rows in `shadow_decisions` collapsed from ~130/day (June 5-9) to ~0 (June 14-18) **despite M37/M39 "fixed" claims** that claimed non-degenerate realized PnL. All 187 unfilled gate-open rows since 06-10 are v1 (active mean-reversion strategy) — the regression is entirely in the active version's shadow series.

**Investigation (D2.0):**
- Ruled out (a) signal-bar ticks absent: 187/187 rows have signal-bar ticks PRESENT, DB join + log evidence decisive.
- Ruled out (b) tick-aggregate partition: all daily `p20260610`…`p20260619` partitions exist and queryable.
- Ruled out (c) deferred-walk durability: no force_close-only rows; unfilled rows are **truly absent** (`simulated_fill IS NULL`), not present-but-unupgraded.
- **Confirmed: wrong-side-of-stop guard rejection on entry-reference mismatch.** `isStopSideValid` (`ShadowStrategyOrchestratorService.ts:392`) validates the strategy's stop against the **tick-derived** shadow entry (`evidence.nextBarOpenPrice`, signal-bar last-tick close) instead of the `reconstructReferencePrice` the strategy drew the stop from. M38's exit-geometry repair tightened the mean-reversion structural stop so it hugs the live reference; a small divergence between tick-derived and event-derived references now flips the stop to the wrong side of the shadow entry → `isStopSideValid` rejects → `simulatedFill: null`. Sampled log: 79 `invalid stop-loss side — skipping open` warnings over 168h window, all true stop-side errors (e.g., `side:long entry:0.6805 stopLoss:0.68835` = stop ~1.15% ABOVE entry — invalid).

**Architect Verdict (2026-06-19):** Reject the shipped `WRONG_SIDE_OF_STOP` typed-miss approach. Live **holds** these positions (live wrong-side guard evaluates against `avgFillPrice` = actual taker fill, within slippage of the SL anchor; shadow evaluates against `nextBarOpenPrice` = signal-bar close, ~1% off the anchor). The shadow rejection censors trades live takes. **Fix shape #1 (preferred):** validate the stop-side against `reconstructReferencePrice` (the anchor the strategy drew the SL from), keep the tick-derived `nextBarOpenPrice` as the fill entry, and let the intrabar walk decide sl/tp/time_stop/force_close. If the tick-derived entry is already past the unchanged SL, the walk records an immediate structural stop-out (bounded ≈ −1R loss), not a 0-qty miss. This restores parity: live holds → shadow holds and lets the walk adjudicate honestly.

**Solution (Implemented):**
- `ShadowStrategyOrchestratorService.runOneShadow` (`:392` / `:961`): `isStopSideValid` now validates against `reconstructReferencePrice` (strategy's own anchor), not `nextBarOpenPrice`.
- `HistoricalFillAdapter.simulateIntrabarStop` walk handles tick-derived entry already past unchanged SL → immediate stop-out at first tick (recorded as `close_reason=stop_loss`, not `missed:true`).
- ADR 0029 amendment rewritten by architect: the shipped "Clarifying note (M40 D2)" was incorrect (it claimed the typed-miss mirrored live; it did not). Revised note records: (a) shadow stop-side check is now validated against `reconstructReferencePrice` (strategy's anchor), (b) fill stays tick-derived (`nextBarOpenPrice`), (c) when tick entry is already past unchanged SL, intrabar walk records bounded ≈ −1R structural loss (not 0-qty miss), (d) §D1.1 "SL never rebased" invariant is **reaffirmed and not touched**.

**Files:**
- `apps/engine/src/strategy/service/ShadowStrategyOrchestratorService.ts` — stop-side re-anchor (`:392` / `:961` predicates).
- `apps/engine/src/strategy/service/__tests__/ShadowStrategyOrchestratorService.D2.spec.ts` — 15 paired tests (re-anchor validation, tick-derived entry, tick entry already past SL → immediate stop-out, walk-resolution close_reason non-degenerate).

### D4 — Paper-safe stuck-row sweeper (SHIPPED)

**Problem:** Zombie `pending_open` row #38 (ZEC) stuck since 2026-06-15 (`state=pending_open`, `qty=0`, never fired `protective.attached` transition). `ReconciliationService` is a no-op under PAPER, so nothing reconciles the orphaned row. Also D1's non-clean-under-halt residual: a permitted close that fails non-cleanly parks in `RECONCILING` with held close slot, and under PAPER has no driver to re-fire or sweep.

**Solution:**
- New `StuckPositionSweeper` service (boot-time + periodic @Interval): sweeps two stuck shapes.
  - **Orphaned `pending_open`** (the #38 ZEC case): transitions via **two-step** `pending_open → reconciling → closed` (legal arrow per state graph), finalizes with `realizedPnl=0` (or null), does NOT increment trade counters (never-filled, not a trade). Exit reason: `FORCE_CLOSE` (existing enum, no new shared change).
  - **`RECONCILING`-parked** (D1 non-clean residual): transitions via **one-step** `reconciling → closed`, **releases held close slot** (`closeCoordinator.release`, idempotent — order-reservation already released by `handleReduceTerminal` non-clean), finalizes. Partial-filled `RECONCILING` rows respect normal finalize contract (realized PnL follows fill).
- Threshold: named constant `STUCK_SWEEP_STALE_MS` (default ≈ protective-attach timeout + margin); `RECONCILING`-parked threshold may reuse same constant.
- Deterministic clock: compares `nowMs >= referenceTs + threshold` using injected `@Interval` boundary clock.
- Scope guard: **PAPER-scoped for `RECONCILING` branch** (live reconciliation owns those rows); **both** `pending_open` and `reconciling` queries filter stale only (no younger than threshold).
- **No exchange call** — works in PAPER (and live).

**Files:**

- `apps/engine/src/execution/const/executionConsts.ts` — `STUCK_SWEEP_EVENT_CLASS`, `STUCK_SWEEP_STALE_MS` constants.

**Test count:** 17 new (StuckPositionSweeper.spec.ts).

**Review:** 2 rounds.
- **R1:** 2 HIGHs (state-graph arrow validation, close-slot release idempotency) + 4 MEDIUMs. After fixes: 0 blockers.
- **R2:** CLEAN.
