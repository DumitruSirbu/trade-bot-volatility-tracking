# M35 — Trade-record integrity (entry-snapshot persistence + wrong-side/sub-cost TP guards)

**Closed:** 2026-06-14

## Problem Statement

Live soak DB analysis of 11 closed positions revealed three critical data-integrity gaps:

1. **Finding 1 (HIGH):** 12 entry-snapshot columns were NULL on every closed position row:
   - `vwap_at_entry`, `atr_at_entry`, `vwap_deviation_at_entry`, `idiosyncrasy_at_entry`, `signal_score_at_entry`
   - `open_interest_at_entry`, `oi_change_5m_at_entry`, `funding_annualized_at_entry`
   - `book_depth_10bps_at_entry`, `spread_at_entry_pct`, `vwap_anchor_type`, `symbol_universe_age_hours`
   
   **Root cause:** `createPositionFromFill` in the execution path never hydrated these columns from the market snapshot available at order intent approval time.

2. **Finding 2 (MEDIUM):** MAE/MFE seed-timing gap — initial MAE/MFE values seeded at position open (entry price = MAE = MFE), but first real-time price tick may arrive seconds later. Sharp pre-first-tick price moves cause understated MAE/MFE. **Deferred to tech-debt.**

3. **Finding 3 (HIGH):** One EDGE/USDT short position was tagged with `take_profit` reject reason despite losing −1.318 USDT, implying the take-profit logic approved a TP on the wrong side of entry. **Root cause:** `computeMeanReversionTakeProfit` can produce a TP-side geometry on the wrong side when VWAP has already moved past the entry price (degenerate configuration).

## Implementation

### Entry-Snapshot Persistence

- **`IOrderIntentApprovedEvent` contract:** Added optional `entrySnapshot?: IMarketSnapshot` field. This is an engine-internal seam; close/reduce/flatten emitters do not populate it (only opening intents carry snapshots).

- **`StrategyService.emitApproval`:** Threads the gate-verdict-stamped snapshot from `RiskGateService.evaluate()` result into the `IOrderIntentApprovedEvent` event object before publication.

- **`ExecutionService.mapEntrySnapshotColumns`:** New mapper function that hydrates all 12 entry-snapshot columns from the snapshot carried in the approved event. Wrapped in try/catch so analytics errors (parse, validation, decimal rounding) never crash the post-fill position insert. Maps:
  - Direct fields: `vwap_at_entry`, `atr_at_entry`, `vwap_deviation_at_entry`, `idiosyncrasy_at_entry`, `signal_score_at_entry`, `spread_at_entry_pct`
  - OI snapshot: `open_interest_at_entry`, `oi_change_5m_at_entry`
  - Funding snapshot: `funding_annualized_at_entry`
  - Book snapshot: `book_depth_10bps_at_entry`
  - Metadata: `vwap_anchor_type`, `symbol_universe_age_hours`

### Degenerate Geometry Guard

- **`isDegenerateReversionGeometry` predicate:** New logic in `evaluateMeanReversion`:
  - **SHORT degenerate** when `vwap >= referencePrice` (TP would be below entry, SL above entry — backwards).
  - **LONG degenerate** when `vwap <= referencePrice` (TP would be above entry, SL below entry — backwards).
  - Fires **before** `buildOpenSignal` so the strategy rejects the signal (sets `reason: DEGENERATE_VWAP_GEOMETRY`) without emitting an approval event.

### Take-Profit Validation at Risk Gate

- **`isWrongSideTakeProfit` predicate:** Added to `RiskGateService.evaluateEntry` (opening intents only). Checks:
  - LONG: `takeProfit <= entryPrice` → wrong side (REJECT).
  - SHORT: `takeProfit >= entryPrice` → wrong side (REJECT).

- **`isTakeProfitBelowCost` predicate:** Checks whether the TP, after accounting for round-trip fees + slippage, would result in a loss:
  - Round-trip cost formula: `entryPrice × (2 × RISK_TAKER_FEE_RATE + 2 × slippageFraction)`
  - Slippage is **doubled** to cover both entry and exit legs.
  - NaN/negative guard on `estimated_slippage_pct` (fail-closed: if slippage unavailable, reject rather than assume zero).
  - Applied only on opening intents (close/reduce intents omit this check).

### Reject & Skip Reason Enums

- `RejectReasonEnum` gains: `TP_WRONG_SIDE`, `TP_BELOW_COST`
- `SkipReasonEnum` gains: `DEGENERATE_VWAP_GEOMETRY`

## Architecture & Decisions

1. **Snapshot carried through engine-internal event, not re-read at fill time** (backtest determinism invariant): The gate-approved snapshot is captured at strategy intent-emission time and threaded through the `IOrderIntentApprovedEvent`. This preserves determinism — the same market state that produced the approval gate-verdict is used for position record-keeping.

2. **Degenerate geometry guard at strategy layer + risk gate backstop**: The strategy layer (`evaluateMeanReversion`) detects degenerate VWAP geometry and skips the signal. The risk gate (`evaluateEntry`) independently checks for wrong-side TP and TP-below-cost. Defense in depth.

3. **Try/catch in column mapper**: Analytics errors during snapshot hydration (missing field, decimal rounding, validation) are caught and logged as WARN. The position insert proceeds with null columns rather than aborting the fill. This prioritizes position lifecycle integrity over perfect analytics columns.
