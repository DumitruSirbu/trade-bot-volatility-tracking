# M41 — Decisions feed outcome clarity + zero-fill audit fix

**Closed:** 2026-06-19 (shared contract + engine mapper + dashboard + execution one-liner)

**Summary:** Operator report showed green **OPEN** badges on Decisions while Positions stayed empty.
Root causes split across milestones: misleading UI (M41 D1), stale paper ticks (M42), and zero-fill
audit insert failures (M41 D2).

**Plan:** [M41-decisions-feed-outcome-and-zero-fill-audit.md](../../plans/archive/M41-decisions-feed-outcome-and-zero-fill-audit.md)

## Deliverables

### D1 — `IDecisionView.outcome` + dashboard Outcome column (SHIPPED)

| Layer | Change |
|-------|--------|
| `packages/shared` | `DecisionOutcomeEnum`; `mapDecisionOutcome()`; `IDecisionView.outcome` |
| `readApiMappers.ts` | `mapDecision()` derives `outcome` from `gate_allowed` + `position_id` |
| `getDecisions.ts` (analysis) | SQL selects `gate_allowed`; same mapper |
| `DecisionsFeed.tsx` | Outcome column + filter; Action badge no longer green for all OPEN intents |

Outcome rules:

| Outcome | Rule |
|---------|------|
| `skipped` | `action === skip` |
| `rejected` | `action === open` and `gate_allowed === false` |
| `approved` | `action === open` and `gate_allowed === true` and no `position_id` |
| `filled` | `position_id` set |

Persistence unchanged — `decisions.action` remains intent for funnel SQL.

### D2 — Zero-fill audit `cashflow` (SHIPPED)

`ExecutionService.recordZeroFillAuditRow` now passes `cashflow: new Money(0)` so NOT NULL
`transactions.cashflow` no longer blocks audit rows on cancelled/zero-fill OPEN/ADD intents.
