# M42 — Paper stale-tick REST refresh before fill simulation

**Closed:** 2026-06-19 (engine + unit tests; post-deploy soak verification pending)

**Summary:** Gate-approved paper opens could miss fills when the WS tick cache was minutes stale at bar-close
execution time. Added an on-demand REST `fetchTickers` recovery path via `PAPER_TICK_REFRESH_REQUEST` so
`PaperFillSimulator` can reseed `StreamingFillAdapter` before simulating the fill — without a
`PaperModeModule` → `ExchangeModule` circular import.

**Plan:** [M42-paper-stale-tick-rest-refresh.md](../../plans/archive/M42-paper-stale-tick-rest-refresh.md)

## Root cause

`PaperMarkPriceSubscriptionBridge` updates `StreamingFillAdapter` from `PRICE_UPDATE_EVENT` (WS
`!ticker@arr`). When a symbol drops out of the batch or WS lags, cache age can exceed
`STREAMING_FILL_STALE_TICK_MS` (5s). `simulateOrderFill` correctly refuses stale ticks but had no
recovery — approved intents ended `filled=false` / `cancelled` with no position.

**Production incident:** 2026-06-19 14:05 UTC — OP/USDT and UNI/USDT, `gate_allowed=true`,
`position_id=null`, log `cached tick stale (age≈1556061ms > 5000ms)`.

## Deliverables

### D1 — Event-driven REST tick refresh (SHIPPED)

| Component | Change |
|-----------|--------|
| `eventConsts.ts` | `PAPER_TICK_REFRESH_REQUEST = 'paper.tick.refresh.request'` |
| `IPaperTickRefreshRequest` | `{ symbol, nowMs }` payload |
| `PaperFillSimulator` | `ensureFreshTickCache()` before fill; inject `EventEmitter2` |
| `MarketDataService` | `@OnEvent` → `fetchTickers()` → `emitPriceUpdate` / `PRICE_UPDATE_EVENT` |

Flow: stale/missing snapshot → `emitAsync(PAPER_TICK_REFRESH_REQUEST)` → REST snapshot → bridge
reseeds adapter → fill proceeds.
