# M47 — R:R Geometry Fix

**Status:** DONE (2026-06-25)

**Branch:** `feat/m47-rr-geometry-fix`

**Root cause fixed:** Structurally inverted Risk:Reward geometry across all strategy cores. Two bugs:
1. **Bug 1 — Uncoupled SL/TP anchors:** SL and TP are computed from independent price references (VWAP/wick vs ATR), so `tp_dist` frequently falls below `sl_dist`. Large spikes blow out the SL while TP stays fixed → R:R collapses.
2. **Bug 2 — Asymmetric momentum fill-rebase:** At fill time, momentum TP rebases to actual fill price (ADR 0045 §D1) while SL stays pinned to static VWAP. Post-fill geometry can be wrong-side/negative R:R even if intent-time R:R passed the gate.

**Impact:** 205 closed live positions, −259 USDT total PnL, 29.8% win rate. 85% of trades entered with R:R < 1.0; 85% of the loss (−212 USDT) sat in that bucket. Breakeven at observed 29.8% win rate would require ~61–80% win rate — the geometry alone guaranteed loss.

### Task 2 — Momentum TP hybrid floor coupling
**Owner:** bot-engine-nestjs  
**Touches:** `momentumCore.ts` (`buildMomentumExit` / `resolveTakeProfitDistance`)

Formula:
```
slDist = |reference − vwapSession|              # existing VWAP stop
atrLeg = atr14 × multiplier                     # existing ATR leg
costFloorLeg = round-trip cost + margin         # existing (M43 D2)
rrFloor = min(slDist × min_rr, max_tp_dist_factor × atr14)   # NEW: cap
tpDist = max(atrLeg, costFloorLeg, rrFloor)     # add rrFloor to existing max()
```

- Couples TP to SL: when ATR would produce R:R below `min_rr`, widen the TP instead.
- VWAP stop **never tightened** (thesis invalidation level must remain valid).
- Cap `rrFloor` at `max_tp_dist_factor × atr14` (BLOCKER 5) to prevent negative/unreachable TP on extreme spikes.
- **Degenerate-geometry skip (BLOCKER 5):** if cap binds and results in `tpDist / slDist < min_rr` or TP price ≤ 0 (SHORT) / absurdly large (LONG), skip signal as degenerate (don't ship the position).
- Thread `tpDist` verbatim into both `takeProfitPrice` and `atrDistance` (M38 single-composite-distance invariant, ADR 0045 §D1.2).

### Task 3 — Mean-reversion SL cap coupling
**Owner:** bot-engine-nestjs  
**Touches:** `meanReversionCore.ts`, `computeStops.ts` (`computeStructuralStop`)

- **Computation order (HIGH 2 — refactor to DTO):** compute `tpDist` first, then derive `slCap = tpDist / min_rr`, then the noise floor.
- **SL cap:** when structural stop would produce R:R below `min_rr`, tighten the SL to `slCap` (don't widen TP — the half-retrace TP is already conservative).
- **Noise floor (ATR-relative):** `slFloor = max(atr_floor_multiplier × atr14, (entry_pct_floor / 100) × entry)`
  - ATR-relative form (binding): adapts to current volatility
  - Percent-of-entry form (sanity bound): guards zero/near-zero ATR edge cases
- **Degenerate-geometry skip:** if `slCap < slFloor`, skip as degenerate (don't ship a hair-trigger stop).
- Introduced `IMeanReversionGeometryContext` DTO grouping related parameters (HIGH 2 clean-code fix).

### Task 4 — Risk-gate R:R backstop
**Owner:** bot-engine-nestjs  
**Touches:** `RiskGateService.ts` (insert after `isTakeProfitBelowCost`), new engine const `MIN_RR_GATE_FLOOR = 1.0` in `riskConsts.ts`

**Check:** `isRewardRiskTooLow(intent)` — computes `tp_dist / sl_dist` on clamped SL and rejects with `RR_TOO_LOW` if **strictly less than** `MIN_RR_GATE_FLOOR` (loose floor; at-floor passes).

**Critical anchor fix (BLOCKER 1):** distances are measured against the **signal reference price** (not `intent.entryPrice` which in backtest is `nextBarOpen` / fill estimate).
- Live: `intent.entryPrice = reconstructReferencePrice(event)` (already correct)
- Backtest: must set a dedicated `referencePrice` field on intent to the signal reference, separate from `nextBarOpen` (fill estimate used by sizer)
- Both paths compute `sl_dist = referencePrice − stopLossPrice`, `tp_dist = takeProfitPrice − referencePrice` (mirror for SHORT)
- Without this anchor parity, the same signal yields different R:R in live vs backtest (invariant 7 broken)

**Division-by-zero guard (BLOCKER 6):** if `sl_dist == 0` (VWAP == reference or degenerate wick), reject with `RR_TOO_LOW` (R:R undefined / infinite risk) rather than divide by zero.

**Validity depends on Task 0 (Option B):** the check is valid only because TP is frozen at signal time. If TP were rebased at fill, the gate would approve a geometry that doesn't match what the position holds post-rebase.

**Design rationale:** gate floor (1.0) is a loose safety net, **not** the core target (1.5). Cores shape geometry by coupling (widening TP / tightening SL); gate only catches edge cases. A 1.5 gate would be a kill-switch (would reject 92% of historical signals), starving the bot of trades and data.

**ADR 0004 amended:** R:R backstop added, two-tier design (core target vs gate floor), signal-reference anchor, strict `<` comparator rationale (soft backstop, unlike cost floor's hard `≤`).

### Task 5a — MFE/MAE seed-timing race fix (RESOLVES TECH-DEBT M7)
**Owner:** bot-engine-nestjs  
**Touches:** `PositionInstrumentor.ts` (`applyEntryTick` new method), `ExecutionService.ts` (inject `PositionInstrumentor`, call sync seed at ~:1056), `ExecutionModule` (import `PositionModule`)

**Root cause (M7):** per-tick MFE/MAE tracking already runs (`PositionInstrumentor.onPriceUpdate` → `applyTick`), but the accumulator is seeded via an **async** `POSITION_OPENED_EVENT` handler that does a DB round-trip. Any `PRICE_UPDATE_EVENT` arriving during that async window hits `onPriceUpdate`, finds no entry in `positionsBySymbol`, and is **silently dropped**. For a volatility-spike strategy, the entry instant is the peak-excursion window, so the most important first-second samples are lost.

**Fix — exact insertion point (BLOCKER 2):** synchronously seed **after `createPositionFromFill` returns and BEFORE `await recordEntryTransactionOrEscalate`** (~:1056 in `ExecutionService`):
1. Call `positionInstrumentor.onPositionOpened(positionRow)` to register the symbol in `positionsBySymbol`
2. Immediately call `positionInstrumentor.applyEntryTick(positionRow)` to seed `mfe_pct = 0, mae_pct = 0` as the initial excursion sample (signed convention: `mfe_pct ≥ 0`, `mae_pct ≤ 0`)
3. Control does not yield to subsequent awaits until both calls complete, so no entry-window tick is dropped

**Why insertion point matters:** a call at the current `POSITION_OPENED_EVENT` emit site (~:1144) would be **after** two awaited I/O round-trips, leaving the drop-race unchanged. The ~:1056 point closes the race by registering the symbol before the next await.

**Signed convention preserved:** seeded `mfe_pct = 0, mae_pct = 0` (percentages, not price levels); subsequent ticks update via `max()` for favorable, `min()` for adverse, yielding correct signed values. No corruption of the convention.

**DI note (BLOCKER 2):** added `ExecutionService → PositionInstrumentor` dependency. Verified no circular cycle; NestJS DI wired. Added live-app smoke test at close to catch registration bugs.

**Result:** all new positions opened after M47 deploys capture entry-window excursion; columns no longer read near-zero. Forward excursion data becomes self-sustaining for post-deploy `min_rr` review.

### Task 5c — Signal-quality data foundation: `position_segment_stats` view
**Owner:** bot-engine-nestjs (migration), bot-scribe (docs)  
**Scope:** read-only analytics view, no strategy logic, no trade path

**View segments closed positions by:** `flow_type`, `symbol`, `strategy_versions_id`, `side`, `hour_of_day`

**Per segment, exposes:**
- `win_rate` (count of profitable positions / count)
- `avg_pnl` (average realized PnL per position)
- `avg_rr` (average R:R ratio at entry: `(tp_price − entry_price) / (entry_price − sl_price)` for LONG, mirror for SHORT)
- `avg_mfe_pct` (average favorable excursion, ≥ 0)
- `avg_mae_pct` (average adverse excursion, ≤ 0)
- `trade_count`

**Critical partition (BLOCKER 4):** by `strategy_versions_id`, not deploy date. M47 bumps geometry-coupled version rows (v1 → v11, v2 → v21, v3 → v31), so the view partitions pre-M47 inverted-geometry trades (old IDs) from post-M47 coupled trades (new IDs) **by construction**, without date arithmetic. Old IDs are the baseline; new IDs are the measurement set.

**Column precondition (HIGH 6):** verify `positions` table persists `stop_loss_price`, `take_profit_price`, `entry_price` before writing the view. If missing, add in migration. Do not ship a view with silently-null `avg_rr`.

**Purpose:** enables M48 signal-quality workstream without a separate data-plumbing milestone. M48 can query segment profitability by flow type / symbol / session without ad-hoc SQL.

**Dependency on Task 5a:** `avg_mfe_pct` and `avg_mae_pct` are only meaningful after 5a fixes the seed-timing race. Pre-5a closed positions read near-zero (entry-window samples dropped). Documented in schema.
