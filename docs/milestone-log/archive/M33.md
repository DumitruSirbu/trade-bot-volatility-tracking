# M33 — Live exit enforcement (time-stop + paper protective simulation + entry cashflow)

**Status:** DONE  
**Date range:** 2026-06-12 to 2026-06-13  
**Source:** `docs/wip/live-exit-enforcement-gap.md` (detected 2026-06-12, resolved M33)

## Outcome

M33 closed three linked defects that left positions stuck indefinitely without exits (primary gap) and one audit gap (entry transaction cashflow):

1. **Live time-stop enforcer** (primary) — implemented `PositionTimeStopEnforcer` event-driven on `price.update`, in-memory deadline index with fast-path scalar, gate-routed close intents with `exitReason = TIME_STOP`, shared dedup registry via `SharedCloseCoordinator` so time-stop WINS over concurrent local monitor breach.
2. **Paper protective simulation** (primary) — paper mode now **does not disarm** the local monitor when exchange-side attach succeeds (in parity with backtest `IntrabarStopSimulator`); SL/TP prices persisted at open time (closing pre-attach crash window); boot re-arm logic re-arms paper `exchange_side` rows from persisted prices.
3. **Entry cashflow explicit zero** (secondary audit) — all entry (open/add) transactions now explicitly write `cashflow = new Money(0)` at call site, closing the null-insertion edge case.

## Bugs caught by reviewers

1. **(HIGH)** `PositionTimeStopEnforcer.handleExpiry` missing release on exception → slot leak forever (fixed: try/catch at enforcer boundary)
2. **(HIGH)** `LocalProtectiveMonitor.handleBreach` missing release on exception → slot leak forever (fixed: try/catch at monitor boundary)
3. **(HIGH)** Reconciliation `flattenForeignPosition` missing expiry listener release → slot leak on halt/dry_run → subsequent closes hang (fixed: added `ORDER_INTENT_EXPIRED` listener scoped to reconciliation's own eventId prefix)
4. **(MUST-FIX)** `ExecutionService.recordClose` emit-side reason literals `'stop_loss'`, `'take_profit'`, `'time_stop'` not using shared `ExitReasonEnum` constants (fixed: constants usage everywhere)
5. **(MEDIUM)** `findTimeStopCandidatesBySymbol` predicate coverage for PENDING_OPEN (added integration test; repo query now returns PENDING_OPEN + OPEN with deadline)

## Deferred to tech-debt

1. **MEDIUM L1 — Time-stop deadline index hardening:** M33 ships minimal in-memory index (correctness + fast-path). Follow-on: symbol-sharded eviction, index/DB consistency self-heal on drift, hot-path profiling under >3 open positions. Owns: bot-engine-nestjs. Milestone: future (M34+).
2. **MEDIUM Q2 — Reconciliation-tick fallback for stale-feed symbols:** `PositionTimeStopEnforcer` fires only on `price.update`. A position on a halted/delisted/feedless symbol receives no ticks and is never swept. Follow-on: a `ReconciliationService`-tick deadline sweep (using event/reconciliation time) as a backstop. Owns: bot-engine-nestjs. Milestone: future.
3. **MEDIUM — PENDING_OPEN mid-run indexing gap:** The deadline index is armed only on `POSITION_OPENED_EVENT` (after PENDING_OPEN→OPEN). A row stalled in PENDING_OPEN is not enforced live until restart (restart rebuilds from `findTimeStopCandidatesBySymbol` which includes PENDING_OPEN). Low likelihood (PENDING_OPEN is transient). Owns: bot-engine-nestjs. Milestone: future.
