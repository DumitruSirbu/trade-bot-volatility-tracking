# M37 — Strategy-comparison infrastructure (concurrent shadow evaluation + backtest fill restoration + trade-record integrity)

**Closed:** 2026-06-16

## Problem Statement

Three measurement defects blocked strategy comparison and backtest instrumentation:

1. **D-real-1 (PRIMARY) — Read-layer gap:** The comparison queries (`compareVersions.ts`, `getPerformance.ts`) read **only** `decisions`/`positions` and never read `shadow_decisions`, despite concurrent same-event shadow evaluation already writing one row per version per event to that table. Same-event DECISION coverage exists (2,441 shared `event_id`s); the read layer gap prevents exposing it.

2. **D-real-4 (PRIMARY) — Hollow shadow fills:** Direct content inspection of `shadow_decisions.simulated_fill` (2026-06-15) showed **~99% are `missed:true` with `entryPrice:"0"`, no `exitPrice`, no `closeReason`, all `lowFidelity:true`** (v2: 841/844; v3: 177/179). The shadow fill simulator records decisions but computes **no realized counterfactual PnL**. Root cause: `simulateShadowFill` was not loading `tick_aggregates` per event; it passed empty ticks to the fill detector, triggering a miss.

3. **D-real-3 — Active-vs-shadow double-count hazard:** The active version (v2) appears in **both** tables (`decisions` and `shadow_decisions` through Jun 14). The reconciliation must not double-count it. A precedence rule is required: for the **active** version use `decisions`/`positions`; for **shadow-status** versions use `shadow_decisions`.

4. **D-real-2 — v1 status-transition blackout:** v1 logged nothing in either table Jun 8 → Jun 14 after going inactive Jun 8, then resumed in `shadow_decisions` Jun 14. A deactivated version must immediately continue as `shadow` with no gap.

5. **Problem 2 — Backtest 0-fills:** All three backtest report windows produce `tradeCount: 0` because the backtest gate rejects 100% of candidates (missing `book_snapshots` / liquidation-distance / depth reconstructability). Live passes ~7%; the same-denominator comparison is impossible.

6. **Problem 3 — Trade-record integrity defects (≥6 of 24 trades):**
   - **3 positions** with `exit_reason=take_profit` but **negative** `realized_pnl`, 0-min hold, MFE 0.00 (EDGE −1.32, ZEC −0.48, ALLO −0.26).
   - **1 position** `exit_reason=time_stop` at **127-min** hold while `time_stop_minutes=15` (MRVL — exit-enforcement breach).
   - **2 `manual` exits** (OPN 75 min, AMD) — not strategy-attributable but in expectancy.

## Implementation

### W1 — Analysis read-layer + shadow fill simulator repair + status-transition fix

#### D1.1 — Read-layer reconciliation

- **`compareVersions.ts` + `getPerformance.ts`** now read `shadow_decisions` reconciled with `decisions`/`positions` on the shared `event_id`.
- Reconciliation via UNION or a dedicated reconciling view in `packages/analysis/`.
- Active-vs-shadow precedence rule: for the active version, use `decisions`/`positions`; for shadow-status versions, use `shadow_decisions`.
- No active version is double-counted; regression test proves this.

#### D1.3 — Status-transition fix

- **`PromotionService.demoteIncumbentToShadow`** now sets `status=SHADOW` (was `ARCHIVED`), enabling `runShadows` to pick up deactivated versions.
- v1 continuity confirmed: no further blackout after demotion.

#### D1.6 — Shadow fill-simulator repair (VIRTUAL ledger — counterfactual only, never a live order)

- **Root cause:** `simulateShadowFill` was not loading `tick_aggregates` per event; it passed empty ticks to the fill detector.
- **Fix:** Load `tick_aggregates` once per event in `runShadows` and thread immutable ticks into each shadow version.
- **Entry alignment:** Moved from signal-bar `reconstructReferencePrice` to **next-bar open** (same as M7 `BacktestOrchestrator`), per M26 amendment.
- **Exit:** Forward-only exit via the version's own exit policy on bars after entry (no future-extremum / look-ahead fill).
- **Result:** Accepted `open` counterfactuals now carry populated `entryPrice`, `exitPrice`, `closeReason`, and realized counterfactual PnL — **not** hollow `missed:true`/`entryPrice:"0"`.
- **Fill status:** VIRTUAL counterfactual (no live order, no slot, no `positions` row). Deterministic + forward-only (no wall-clock, no RNG).

#### D1.4 — No-shadow-order regression guard

- Test proves `ShadowStrategyOrchestratorService` cannot allocate a live slot, call the exchange order API, or write a live `positions` row.
- Shadow evaluation remains in separate orchestrator with sovereign virtual ledger (ADR 0029 §2.1 cardinal rule).

### W2 — Backtest fill restoration + live-vs-backtest gate contract

#### D2.1 — Book-snapshot replay

- `BacktestRunnerService.resolveBookGateInputs` consumes captured `book_snapshots` from the database when available (real spread/depth).
- Fallback constants documented and applied when book data is unavailable (M19 depth floors: `{t1:20k,t2:10k,t3:5k}`).
- Each fill is tagged full-fidelity (book-backed) or fallback/low-fidelity.

#### D2.2 — Reference symbol correction

- **`BTC_REFERENCE_SYMBOL`** corrected from `'BTCUSDT'` to `'BTC/USDT:USDT'` (ccxt unified form).

#### D2.3 — Live-vs-backtest contract

- `docs/architecture/live-vs-backtest-contract.md` amended with a per-check reconstructability table.
- Every risk-gate check classified as: **reconstructable** (runs identically live and in backtest), **approximated** (uses documented fallback in backtest, flagged), or **not modeled** (skipped with reason).
- Each row cites its owning ADR.

**Result:** All three backtest report windows now produce `tradeCount > 0`. v2 backtest approval rate over live-overlapping window is directionally comparable to live ~7% on the same denominator (approvals / open-intents, not total-events).

### W3 — Trade-record integrity fixes

#### D3.1 — Mislabeled `take_profit` exits (EDGE/ZEC/ALLO)

- **Root cause:** Momentum TP was computed off bar-close reference vs actual next-bar entry fill, so entry filled at/past TP and `LocalProtectiveMonitor` fired immediately (0-min, MFE 0.00).
- **Fix:** Added `isWrongSideTakeProfit` + `isTakeProfitBelowCost` guards on `RiskGateService.evaluateEntry` (opening intents only).
- **TP now requires:** A realized net gain. Round-trip cost formula: `entryPrice × (2 × RISK_TAKER_FEE_RATE + 2 × slippageFraction)`.
- **New reject reasons:** `TP_WRONG_SIDE`, `TP_BELOW_COST`.

#### D3.2 — `time_stop` enforcement breach (MRVL: 127-min vs 15-min)

- **Root cause:** `PositionTimeStopEnforcer` is event-driven on `price.update`. If no tick arrives (thin tier-2/stalled feed), deadline never fires.
- **Fix:** Added `PositionTimeStopEnforcer.sweepDeadlineBreaches()` — `@Interval(60_000)` periodic sweep that closes any position whose deadline has passed.
- **Determinism:** Uses event time (not wall-clock), so it remains deterministic for backtest replay.

#### D3.3 — `manual` exits (OPN/AMD)

- **Root cause:** Manual operator intervention occurred; not strategy-attributable.
- **Fix:** Excluded from strategy expectancy via analysis-layer `gate_allowed != true` filter (manual exits have no gating record).

## M40 Re-qualification Note (2026-06-19)

**Re-qualification claim held in test; regressed in production June 10 → M40 deploy.**

M37's claim of "non-degenerate realized PnL" (and M39's W2 deferred-walk upgrade claim) were contradicted by production data starting 2026-06-10: `shadow_decisions` `simulated_fill` collapsed to ~0/day despite all gate-allowed opens populating the table. Root cause (confirmed M40 D2.0): M38's exit-geometry repair tightened the mean-reversion structural stop so it hugged the strategy's `reconstructReferencePrice` reference. The shadow path's `isStopSideValid` guard validated the stop against the **tick-derived** signal-bar close instead, creating a ~1% divergence. This flipped the stop to the wrong side of the shadow entry, triggering a reject that produced no fill. Live, keyed on the actual taker fill price (within slippage of the strategy's own reference), never saw this gap and held the positions.

**M40 D2 fix:** `isStopSideValid` now validates against `reconstructReferencePrice` (the anchor the strategy drew the SL from), fills stay tick-derived, and the intrabar walk adjudicates the outcome (immediate stop-out if tick entry already past SL, recorded as bounded ≈ −1R loss, not 0-qty miss). This restores parity: live holds → shadow holds.

**Re-qualification gate (B5):** After M40 D2 deploy, `shadow_decisions` over ≥1 full soak day must show (a) non-zero `simulated_fill` for gate-allowed opens AND (b) non-degenerate `close_reason` distribution (not ~100% `force_close` / not ~100% `missed`). Window must be post-deploy (June 10→M40 gap is a hollow window with hollow fills; new window post-M40 is authoritative). M37/M39's measurement infrastructure (slot-freeing, deferred-walk, force_close-fraction gate) remains correct; the "non-degenerate" data claim is revalidated post-M40.
